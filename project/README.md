# 같은 나이, 다른 시대 — 3세대 연표 에이전트

라이너 .EXE-THON 2026 출품작 (Team Nexus, 개인 참가)

## 무엇을 하나요

아버지의 스무 살이 어땠는지, 우리는 모르고 삽니다. 부모 세대의 젊은
시절은 이야기로만 전해지고, 그 시절의 세상과는 연결되지 않습니다.

이 에이전트는 세 세대의 생년을 받으면 **연표의 축을 연도가 아니라
나이로 바꿔** 정렬합니다. 나이마다 각 세대가 그 나이였던 연도를
계산하고, 그 연도의 한국(주요 사건·물가와 생활상·유행과 문화)을
조사해 출처와 함께 채웁니다. 개인 이벤트(연도 + 한 줄)를 넣으면
그 나이 행에 시대 맥락과 나란히 놓입니다.

여기에 사진 한 장을 더하면, 각 셀에 **시대 초상**이 붙습니다.
세 세대의 20살 행에서는 1965년의 흑백 초상, 1992년의 컬러 필름
초상, 2032년의 미래 스타일 초상이 한 화면에 나란히 정렬됩니다.

## 초상 규칙

- 입력 사진은 가운데 세대인 **"나"의 사진 1장**이 기본입니다.
- **세대별 실물 사진이 있으면 그 사진이 해당 세대의 기준**이 되고,
  없는 세대만 본인 사진에서 파생합니다. 우선순위는 세대별 독립
  적용입니다 (예: 아버지 사진만 있으면 아버지는 실물 기준, 아들은
  본인 사진 파생).
- 파생 방향 — 아버지는 본인을 **나이 든 방향 + 아버지 시대**로,
  아들은 **젊은 방향 + 아들 시대**로. 초상은 연표의 행(나이)에 맞춰
  그 나이의 얼굴로 만듭니다.
- 모든 초상에는 기준(실물/파생)을 표시하고 **항상 "AI 합성" 라벨**을
  붙입니다. 진짜 옛 사진인 척하지 않습니다.
- 초상은 입력된 세대에 대해서만 만듭니다. 아들 생년이 입력되지
  않으면 아버지와 나의 **2세대만** 생성합니다.

## 정직성 규칙

- **미래는 전망으로 강제** — 현재보다 뒤의 연도는 조사 결과가
  뭐라고 하든 "전망"으로 표기하고, 문장은 추세·전망 자료 기반의
  "~로 전망된다"로만 씁니다.
- **출처 없는 셀 금지** — 근거를 찾지 못한 연도는 내용을 지어내지
  않고 빈 셀로 남깁니다.
- **초상은 합성이라고 밝힌다** — 기준(실물/파생)과 AI 합성 라벨을
  모든 초상에 표시합니다.

## 문장 원칙 — 감동은 디테일의 병치에서

- 감정 형용사와 상투적 감성 문구("그리운 그 시절" 류)는 쓰지
  않습니다. 회고문·하이라이트·카드 전부 같은 원칙입니다.
- 시대 셀은 출처 있는 구체 디테일로 채웁니다 — 그해의 물가·급여,
  교통수단, 연락 수단, 유행가와 영화 같은 검증 가능한 사실.
- 감동 장치는 사실의 병치뿐입니다. 같은 나이 행에서 세대 간 사실이
  대조되게 놓고(예: 20살의 연락 수단 — 편지와 전보 / 삐삐와
  공중전화 / AI 비서), 해석 문장은 최소로 둡니다.

## 공유

- `POST /chronicle` 결과에는 `share_id`가 발급됩니다.
  `GET /share/{share_id}`는 로그인 없이 열리는 읽기 전용 뷰로,
  연표 매트릭스·회고문·초상 프롬프트를 그대로 돌려줍니다.
- `GET /share/{share_id}/card`는 "같은 나이" 하이라이트를 이미지
  카드 1장(SVG)으로 내보냅니다. 사실 대조 세대별 한 줄 + 연도가
  들어가 메신저로 보내기 좋은 형태입니다.
- 공유받은 가족이 자기 생년·사진을 추가해 연표를 확장하는 흐름은
  기획서의 확장 설계로만 명시했고, 이번 구현 범위에는 넣지
  않았습니다. 공유 저장소는 데모용 인메모리입니다.

## 데모 시나리오

```bash
# 시나리오 1 — 3세대 + 사진 1장 (할아버지 1945 / 나 1972 / 아들 2012)
curl -X POST localhost:8078/chronicle -H 'Content-Type: application/json' \
  -d @samples/chronicle_demo.json
# -> 20살 행: 1965(흑백·파생) / 1992(컬러 필름·실물) / 2032(전망·미래 스타일·파생)
#    아들의 미래 연도는 전부 전망, 조사되지 않은 연도는 빈 셀

# 시나리오 2 — 아들 없음(2세대) + 사진 없음
curl -X POST localhost:8078/chronicle -H 'Content-Type: application/json' \
  -d @samples/chronicle_demo_two_gen.json
# -> 2세대만 생성, 사진이 없으면 연표는 텍스트만으로 동작
```

mock 시대 자료는 널리 확인 가능한 역사 사실만 담았습니다
(1945 광복, 1965 한일기본조약, 1992 바르셀로나 올림픽·서태지 데뷔,
2012 강남스타일 등). 미래 연도(2032·2052)는 통계청 장래인구추계
등 전망 자료 기반 문장으로만 수록했습니다.

## Liner Platform 연동 — 상태

- API 키는 환경 변수로만 관리합니다 (코드에 직접 적지 않습니다).
- `.env.example`을 복사해 `.env`를 만들고 `LINER_API_KEY`를 채우세요.
- 키가 없거나 호출이 실패하면 mock 시대 자료로 폴백해 전체 흐름을
  그대로 시연할 수 있습니다. mock에 없는 연도는 빈 셀이 됩니다.
- **현재 상태 (2026-11-19): API 키 발급 완료, 크레딧 $200 확인.
  실호출 검증은 아직 진행 중**이라, 현 제출 스냅샷의 시대 자료는
  mock 엔진 기준입니다.
- 시대 초상도 같은 원칙입니다. 초상 모듈은 프롬프트 생성과 생성
  연동 인터페이스까지 마련돼 있고, 실제 이미지 생성 연동은
  플레이스홀더 상태입니다 (응답의 status 필드로 구분됩니다).

## 구조

- `app/main.py` — FastAPI 진입점 (`POST /chronicle`, `GET /share/{id}`, `GET /share/{id}/card`, `GET /health`)
- `app/models.py` — 입력/출력 스키마 (세대·셀·초상·전망·공유 카드 정의)
- `app/chronicle.py` — 연표 파이프라인 (나이 정렬, 회고문, 사실 대조 하이라이트, 한 장 연표)
- `app/era.py` — 시대 조사 (Liner 우선, mock 폴백, 전망 강제·출처 규칙)
- `app/era_fixtures.py` — mock 시대 자료 (구체 디테일 + 대조 한 줄 + 전망 자료)
- `app/portraits.py` — 시대 초상 (기준 판정, 파생 규칙, 시대별 스타일, 생성 연동 지점)
- `app/share.py` — 공유 저장소와 하이라이트 카드(SVG) 렌더러
- `app/liner_client.py` — Liner Platform 호출 (키 없으면 mock 폴백)
- `samples/` — 데모 시나리오 입력 2건
- `tests/` — 단위 테스트 (나이 정렬·전망 강제·출처 규칙·이벤트 배치·초상 규칙·엔드포인트)
